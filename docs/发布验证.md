# 发布验证

本页说明首个公开快照的检查范围。历史的阶段报告记录旧开发环境，不作为当前 Git 提交的通过凭证。可运行的入口是 [独立演示](../deployment/demo/README.md)；本文件不声明已完成生产环境上线验收。

## 发布检查结果

| 检查 | 结果与边界 |
| --- | --- |
| 发布文件 | 检查凭据模式、私有路径以及数据库种子中的非允许数据；远端开发配置、日志、离线镜像和业务快照不随源码发布。 |
| MySQL 种子 | 在全新的临时 MySQL 8.0.35 中分别验证独立演示和本机开发初始化。两种方式均创建 20 个上架商品、96 个 SKU、各一个合成会员和管理员；初始订单和登录日志为空。重复执行本机账号初始化没有新增重复记录。 |
| 演示资源 | 检查种子引用的图片全部随演示分发。开发准备脚本生成独立口令和匹配的 BCrypt 哈希，不使用固定的开发口令。 |
| Python 与部署工具 | 在不含本机配置的源码副本中，智能体 436 项通过、207 项需要专用集成环境而跳过；部署测试 38 项通过，Ruff 和基础设计检查通过。 |
| 服务部署 | 可在支持 Linux 容器的环境按下方步骤复验。离线静态检查与 MySQL 测试不代表执行了完整 Docker 联调，也不覆盖真实模型、知识索引和交易全链路。 |

独立演示保留两个公开且仅供本机的合成账号；请勿把这些账号或生成的环境配置用于公网部署。禁止将真实用户数据复制到公开演示库。

## 复现发布检查

在源码仓库的根目录运行：

```sh
python3 -m unittest discover -s deployment/test -p test_release_inputs.py
python3 deployment/check-secrets.py
```

需要检查 Python 行为时，在 `mall-agent` 下使用锁定依赖运行 `uv sync --locked` 和 `uv run pytest -q -ra`。数据库集成测试需要独立的测试服务；未配置时以跳过记，不当作通过。前端与 Java 的构建入口在 [独立演示的 Dockerfile](../deployment/demo/) 中。

## 复现自包含演示

按[独立演示指南](../deployment/demo/README.md)用新卷启动默认 `fixture` 栈，再运行 `python3 smoke.py`。冒烟脚本覆盖双端登录、商品、中文搜索、上传、流式测试回复和进入人工队列。真实供应商与交易链路需要单独验收。结束时按指南停止演示，不操作已有业务数据库。
