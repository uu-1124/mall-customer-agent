# 本机联调指南

本文介绍本机运行 Java、Python 与两个前端，Linux 服务器只运行中间件的分布式联调方式。第一次体验项目可直接使用 [Docker Compose 独立演示](../deployment/demo/README.md)，不需要租用服务器或连接开发环境。

## 环境与初始化

- 本机：JDK 17、Maven、Node.js 22、Python 3.13、uv。匹配项目锁文件安装依赖。
- 服务器：Linux x86-64、Docker 和 Compose v2。商城与智能体的数据、凭据、日志及离线镜像不跟随源码发布。新环境使用干净数据、独立账号和 SSH 配置。
- 管理端和买家端的本地 API 地址指向 `http://127.0.0.1:8201`。不要将本地开发配置对外暴露。

在新的开发副本中，从根目录运行下列命令生成本机私有配置；已有环境不要为了演示重复初始化或覆盖数据库：

```powershell
npm ci --prefix deployment
node deployment/prepare.cjs
npm ci --prefix mall-app-web
npm ci --prefix mall-admin-web
```

`prepare.cjs` 生成 `deployment/secrets.json`、中间件编排和 MySQL 本机演示账号初始化脚本。首次生成的演示口令是随机的；已有配置保留原值，运行脚本不会连接数据库修改现有账户。将生成的配置与 SQL 放到受控的开发环境中，勿提交至 Git。独立演示的商品图随源码发布；本机图像目录需要单独准备。

以 [`deployment/.dev-ssh.example.json`](../deployment/.dev-ssh.example.json) 为模板创建本机 SSH 配置，启用本地端口转发并使用服务器回环监听。智能体还需要 PostgreSQL、服务账号、数据迁移及对象存储；如启用知识检索，再配置 Milvus。详细步骤见[智能体开发与运行](../mall-agent/README.md#本机启动)及[部署索引](../deployment/README.md)。

## 运行与修改

确认生成的 Java 配置、JAR 和智能体依赖已准备好后，在项目根目录运行：

```powershell
.\deployment\start-local.ps1
# 停止受管理的本机进程，不停止服务器容器
.\deployment\stop-local.ps1
```

脚本参数和 `MALL_JAVA_HOME` 可用于指定本机工具路径。更多脚本见[部署目录](../deployment/README.md#三目录索引)。管理器启动只表示进程在拉起，仍需确认网关、数据库和智能体就绪。日志默认在忽略目录 `deployment/.run/`。

## 访问与端口

| 本机入口 | 用途 |
| --- | --- |
| `http://127.0.0.1:5173/` | 买家端及商品咨询。 |
| `http://127.0.0.1:5100/` | 管理端、接待工作台和知识管理。 |
| `http://127.0.0.1:8201/actuator/health` | 网关健康检查。 |
| `http://127.0.0.1:8099/readyz` | 智能体就绪检查。 |

SSH 隧道的本地端口包括 MySQL `13306`、Redis `16379`、MongoDB `27018`、RabbitMQ `15672`、Nacos `18848` / `19848`、Elasticsearch `19200`、MinIO `19000`、PostgreSQL `15432`、Milvus `19530`（启用时）。完整映射见[部署索引](../deployment/README.md#本机开发时的端口映射)。不要把数据库和中间件端口直接放到公网。

先用合成账号验收登录、商品检索和对话，再按需验证人工接待、交易确认和知识来源。独立演示的检查范围见[发布验证](发布验证.md)。
